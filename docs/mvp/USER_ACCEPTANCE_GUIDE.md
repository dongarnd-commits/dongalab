# DATCO ONE — 사용자 인수 안내

대상은 Draft PR #18의 보완 버전이다. PR #18은 PR #17의 통합 개발 결과 위에 추가한 변경이며 두 PR의 병합·종료나 main 반영을 수행하지 않는다. 실제 접속 주소·실행 Commit·계정 안내·안전 중지 방법은 새 로컬 환경의 보호 RUNBOOK.md 한 곳에서 확인한다. 기존 8443·8444는 이 보완 버전으로 전환하지 않는다.

## 시작 전

- 현재는 **인수환경 준비와 비민감 자료 점검** 단계다. 개발·자동검증·환경 준비가 실기업 평가나 최종 인수 완료를 의미하지 않는다.
- 실제 동아테크놀로지 자료는 사용범위·접근자·보존·삭제/백업 승인을 받은 뒤 사용자가 직접 제품 화면에 입력한다. Codex 대화·첨부·도구 결과로 원문을 보내지 않는다. 제품의 외부 AI 미설정과 개발용 Codex의 문서 열람은 별개다.
- 역할별 시험 자격은 보호 CREDENTIALS.txt에 있다. 이것은 환경 점검용 시험계정이며 실제 임직원의 개별 접근권한·공유 방법은 별도 승인한다.
- loopback 전용이므로 해당 PC에서만 접속한다. 새 방화벽이나 시스템 인증서 신뢰를 자동으로 추가하지 않는다. 로컬 시험 인증서의 공개 정보는 보호 RUNBOOK에서 확인한다.
- 기술 담당자가 실행 SHA, Web/API/Worker/DB/파일 식별, 로그인·Scope·다운로드 차단, 중지/재개·로그 보호·외부 AI 미설정을 자동 점검한다. 사용자에게 이 검증을 반복 요청하지 않는다.

## 사람이 확인할 세 묶음

| 묶음 | 제품에서 할 일 | 남길 판단 |
| --- | --- | --- |
| 1. 회사 자료와 문제·목표 | 승인된 자료로 기업정보·재무정보·개선요구를 입력한다. 원문과 분석 요약을 비교하고 틀린 값·미확인 항목만 정정한다. 필요한 답변·기업 확인과 운영자 공식 확정은 각자 담당 역할로 수행한다. | 실제 자료와 정리된 현황·문제·목표가 일치하는가? 누락·추론·자료처리 한계가 명확한가? |
| 2. 실제 DMP 제공범위 | 이미 준비된 원천649개에서 추천된 일부 기능을 확인한다. 선택한 기능·실제 릴리스·제공범위·조건·필요 연계의 근거를 담당자가 확인한다. 모듈 추가/교체 후 필요한 관계도 다시 확인한다. 전체649개를 다시 입력하거나 전부 검토할 필요는 없다. | 실제로 제공할 수 있고 해당 요구의 해결·부분·미해결 범위가 적절한가? |
| 3. 고객 사용성과 문서 | 현재 구성의 내용과 다음 행동을 이해할 수 있는지 확인한다. 실제 공식 공고·검토 근거가 있어 기존 제안 Guard를 통과한 경우에만 동일 Version의 DOCX/PDF 내용·표현·파일을 보고 지정 기업에 전달한다. | 고객이 이해할 수 있고 본문·범위·조건·남은 확인사항이 정확한가? 필요한 수정은 무엇인가? |

불필요한 입력 반복은 문제로 기록한다. 미리 채워진 역할·설명을 무조건 다시 입력할 필요는 없다. 미검증 초안은 남길 수 있지만 고객 제안은 제공·해결범위·필요 연계의 실제 검토를 거쳐야 한다. 분석 후보 확인, 기업 확인, 운영자 공식 확정, 제안내용 검토와 최종 전달은 서로 다른 책임이므로 생략하지 않는다.

## 원천649개를 해석하는 법

649개는 승인된 원본 해시를 유지한 실제 DMP 기능 목록이다. 원본에는 2026-10-14 사용자의 제공 가능 주장과 설명이 있으나, 개별 관리 릴리스·정확한 부모 릴리스·현재 적용범위·등록 연계 증빙은 별도다. 시스템은 이를 자동 VERIFIED로 승격하지 않는다. 기능의 원문 분류가 실제 검증된 배포 모듈이라는 뜻도 아니다.

기능 검색·초안 생성·저장·재조회 시험과 추천 정답률·실제 납품 가능성 평가는 구분한다. 합성 원천2개로 성공한 전체 UI 시험도 실제649개 동작 시험과 별도다. 필요한 추가 확인사항은 추천된 항목에 한해 보호된 원천 검토 목록을 참고한다.

등록된 관계가 없는 변경 구성에서 모듈이 독립적인지 실제 연계가 필요한지는 현재 자료만으로 자동 확정할 수 없다. 필요한 관계·근거는 실제 담당자가 확인하고, 독립 구성 승격의 추가 정책이 필요하면 그 부분만 결정한다. 모든 모듈을 무조건 연결하거나 근거 없는 면제로 통과시키지 않는다.

## 정상적인 중단과 보류

새 실제자료 준비 환경에는 가짜 공고나 DEMO 매칭 결과를 넣지 않는다. 공식 공고가 없으면 구성 검토까지 진행하고 정부사업 매칭·정식 제안 전달은 보류한다. 자격·제공 근거·필수 연계가 미확인인 경우 화면의 차단 이유를 남긴다. 업종을 바꾸거나 미해결 문구를 삭제해 인수를 통과시키지 않는다.

공고·자격이 없어 DOCX/PDF를 생성할 수 없으면 문서 묶음은 **인수 보류**로 기록한다. 이전 합성 시험의 문서 성공을 실기업 문서 인수로 대체하지 않는다.

## 기록과 종료

각 묶음마다 '일치/수정 필요/근거 부족/보류'와 해당 Version, 필요한 화면·파일만 보호 evidence/에 남긴다. 비밀번호·토큰·민감 원문을 이슈 본문·Git·PR·Codex에 복사하지 않는다. 기술 오류는 화면의 업무 안내를 따르고, 담당자가 요청할 때만 상세 오류 기록을 연다.

잠시 중지할 때는 보호 폴더의 STOP.cmd를 사용한다. DB·파일·계정·이력은 유지되고 START.cmd로 같은 환경을 재개한다. 실행 Commit이 달라지거나 상태가 비정상이면 기술 담당자가 확인한다. 실제자료와 백업의 삭제는 승인된 보존 정책과 소유권 검증 후 별도로 수행하며 인수 중 초기화·CLEANUP을 하지 않는다.

실제자료 사용 전 한 번에 승인할 항목은 통합 보고서 DMP_ASSET_AUTO_COMPOSITION.md의 자료·접근·보존·삭제/백업 제안표에 모아두었다. 세 묶음이 끝난 뒤에도 사용자 최종 인수와 main 병합·운영 반영은 별도 판단이다.
